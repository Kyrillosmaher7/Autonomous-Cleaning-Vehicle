# Version 2 — Autonomous Cleaning Vehicle

## 1. Overview

Version 2 (V2) extends the Version 1 reinforcement-learning environment by introducing a more dynamic and realistic cleaning scenario.

While V1 operates with static obstacles and a fixed set of dirty cells, V2 introduces environmental changes during an episode and limits the information available to the learning agent.

The objective is to train an agent to continue navigating and cleaning effectively when obstacles can change, new dirty cells can appear, and the agent cannot observe the complete environment.

V2 builds on the stable V1 environment, battery system, charging station, reward system, and Q-Learning pipeline before introducing algorithmic changes in later versions.

---

## 2. V2 Objectives

The main objectives of V2 are:

* Introduce dynamic obstacles.
* Allow obstacles to change during an episode.
* Introduce dirt appearing over time.
* Allow the environment to change while the vehicle is operating.
* Introduce partial observability.
* Define an observation space separate from the complete environment state.
* Provide local observations around the vehicle.
* Preserve the existing battery and charging system from V1.
* Preserve the existing movement action space.
* Adapt the Q-Learning pipeline to the V2 environment.
* Define appropriate termination conditions for a dynamic environment.
* Maintain deterministic and reproducible simulations through configurable random seeds.
* Provide automated unit tests for the new V2 components.
* Train and evaluate the Q-Learning agent in the dynamic environment.
* Compare V2 performance against the V1 baseline.

---

## 3. Environment

The V2 environment remains a rectangular discrete 2D grid.

Each position is represented using:

```text
(row, column)
```

The coordinate system remains:

```text
row    → increases downward
column → increases to the right
```

The environment contains:

* Empty cells
* Dirty cells
* Static obstacles
* Dynamic obstacles
* Vehicle position
* Charging station
* Battery state

Unlike V1, the environment can change during an episode.

The main dynamic components are:

```text
Dynamic Obstacles
        +
Dynamic Dirt
```

The static parts of the environment, such as the configured grid dimensions and static obstacle layout, remain unchanged during an episode.

---

## 4. State Representation

The V2 environment maintains a complete internal state describing the current situation.

The environment state contains information such as:

```text
State
├── position
├── dirty_cells
├── battery
└── dynamic_environment_state
```

The vehicle position is represented as:

```text
(row, column)
```

Remaining dirty cells are represented as a `frozenset` of positions.

The battery represents the remaining energy available to the vehicle.

Dynamic environment state represents information that can change during an episode, such as dynamic obstacle positions and other environment changes.

The state remains immutable and hashable where it is used by the tabular Q-Learning implementation.

Static environment information such as the static obstacle layout remains part of the environment rather than being unnecessarily duplicated in every state.

---

## 5. Observation Space

V2 introduces a distinction between the complete environment state and the information available to the agent.

In V1, the environment is fully observable.

In V2, the agent receives a limited observation of the environment.

The relationship is:

```text
Environment State
        │
        ▼
Observation Function
        │
        ▼
Agent Observation
```

The agent may only observe a local region surrounding the vehicle rather than the complete grid.

For example, a local observation can be represented as:

```text
? ? ? ? ?
? ? ? ? ?
? ? R ? ?
? ? ? ? ?
? ? ? ? ?
```

where:

```text
R = vehicle
? = information outside the available observation
```

The observation space is intentionally kept simple in V2 so that the project can study partial observability without introducing deep neural networks at this stage.

---

## 6. Dynamic Obstacles

V1 uses static obstacles.

V2 introduces dynamic obstacles that can change position during an episode.

The environment therefore changes from:

```text
Static obstacles
```

to:

```text
Static obstacles
+
Dynamic obstacles
```

A dynamic obstacle may move between valid grid positions according to the configured environment dynamics.

The environment must ensure that:

1. Dynamic obstacles remain inside the grid.
2. Dynamic obstacles do not occupy invalid cells.
3. Static obstacles remain unchanged.
4. The vehicle cannot move into an occupied obstacle cell.
5. Dynamic obstacle updates are reproducible when a random seed is configured.

Dynamic obstacle behavior is controlled by the environment rather than by the agent.

---

## 7. Dynamic Dirt

V1 starts an episode with a predefined set of dirty cells.

V2 allows new dirty cells to appear while the vehicle is operating.

The environment therefore changes from:

```text
Initial dirty cells
        ↓
Clean until empty
```

to:

```text
Initial dirty cells
        ↓
Cleaning
        ↓
New dirt may appear
        ↓
Cleaning
        ↓
New dirt may appear
```

New dirty cells must satisfy the environment's valid-cell constraints.

For example, new dirt should not be placed on:

* Obstacles
* Invalid grid positions

The probability and rules governing dirt generation should be configurable so that different experiments can be performed consistently.

---

## 8. Environment Updates

V2 introduces an environment update mechanism that allows dynamic elements to change during an episode.

A simplified V2 environment step is:

```text
Agent Action
      │
      ▼
Vehicle Movement
      │
      ▼
Battery Update
      │
      ▼
Cleaning
      │
      ▼
Dynamic Obstacle Update
      │
      ▼
Dynamic Dirt Update
      │
      ▼
Reward Calculation
      │
      ▼
Next State / Observation
      │
      ▼
Episode Termination
```

The exact ordering of these operations is part of the V2 environment specification and must remain deterministic when the environment is configured with a fixed random seed.

---

## 9. Battery and Charging

V2 preserves the battery and charging system introduced in V1.

The battery remains part of the vehicle state.

The charging station remains a designated location where the vehicle can recharge.

The existing battery behavior is not replaced by V2.

Instead, V2 introduces a more difficult environment around the existing battery system.

The vehicle must therefore operate while dealing with:

```text
Dynamic environment
        +
Battery constraints
        +
Cleaning objectives
```

More advanced battery-planning strategies remain outside the main V2 objective.

---

## 10. Action Space

V2 preserves the V1 discrete movement action space.

The available actions remain:

```text
UP
DOWN
LEFT
RIGHT
```

Each action continues to correspond to a position delta:

| Action | Delta     |
| ------ | --------- |
| UP     | `(-1, 0)` |
| DOWN   | `(1, 0)`  |
| LEFT   | `(0, -1)` |
| RIGHT  | `(0, 1)`  |

The action representation continues to use the existing `Action` enum.

V2 does not introduce additional movement actions.

The primary change in V2 is therefore the environment and observation model rather than the basic movement action space.

---

## 11. Movement

Vehicle movement continues to follow the V1 movement rules.

For every action:

```text
current position + action delta
```

The resulting position is checked against the current environment.

A movement is valid when:

1. The destination is inside the grid.
2. The destination is not a static obstacle.
3. The destination is not occupied by a dynamic obstacle.

If the movement is invalid, the vehicle remains in its current position according to the environment's invalid-action behavior.

Unlike V1, the set of occupied cells can change during an episode because dynamic obstacles may move.

---

## 12. Cleaning

Cleaning continues to occur when the vehicle reaches a dirty cell.

When the vehicle reaches a dirty cell:

```text
dirty cell
    ↓
cleaned
    ↓
removed from remaining dirty cells
```

For example:

```text
Before:

dirty_cells = {
    (2, 3),
    (5, 5),
    (7, 1)
}
```

After reaching `(2, 3)`:

```text
dirty_cells = {
    (5, 5),
    (7, 1)
}
```

Unlike V1, however, the environment may subsequently generate additional dirty cells.

Therefore:

```text
dirty_cells == empty
```

does not necessarily mean that the V2 task can immediately terminate if dirt generation is still active.

---

## 13. Episode Termination

V2 requires additional termination rules because the environment can change during an episode.

The episode can terminate when the cleaning task has been successfully completed according to the configured dirt-generation rules.

A successful completion condition may therefore require:

```text
No remaining dirty cells
+
No further dirt generation
```

The episode may also terminate when:

```text
Maximum steps reached
```

The environment may also define failure conditions for situations such as battery depletion or other configured failure events.

The final termination rules will be fixed before the V2 training experiments are performed.

---

## 14. Reward Function

V2 preserves the main V1 reward structure as the initial baseline.

The V1 reward configuration is:

| Event                 | Reward |
| --------------------- | ------ |
| Valid movement        | `-1`   |
| Invalid movement      | `-2`   |
| Cleaning a dirty cell | `+10`  |
| Completing the task   | `+20`  |

The reward system remains configurable through `RewardConfig`.

V2 may introduce additional rewards or penalties for dynamic-environment events if required by experimentation.

Possible events include:

* Dynamic obstacle collision
* Environment-related failure
* Successful completion under dynamic conditions

Any new reward values will be configurable and experimentally evaluated rather than being treated as fixed values from the beginning.

---

## 15. Agents

V2 continues to use the agent architecture established in V1.

The existing agent strategies remain useful for comparison and testing.

### Random Agent

The Random Agent selects actions without learning a useful policy.

It provides a baseline for performance in the dynamic environment.

### Greedy Agent

The Greedy Agent selects actions based on remaining dirty cells.

Its performance in V2 provides a useful comparison because newly appearing dirt and dynamic obstacles can make simple distance-based decisions less effective.

### Q-Learning Agent

The Q-Learning Agent continues to use a tabular Q-function.

However, V2 introduces a new challenge:

```text
Complete Environment State
        ≠
Agent Observation
```

The Q-Learning implementation must therefore operate using the information available to the agent through the V2 observation model.

---

## 16. Q-Learning

V2 continues to use tabular Q-Learning.

The standard Q-Learning update remains:

```text
Q(s,a) ← Q(s,a) +
         α [r + γ max Q(s',a') - Q(s,a)]
```

where:

* `s` = current agent state or observation
* `a` = selected action
* `r` = received reward
* `s'` = next agent state or observation
* `α` = learning rate
* `γ` = discount factor

The agent continues to use epsilon-greedy action selection during training.

The purpose of V2 is not to introduce a new learning algorithm.

Instead, V2 evaluates how the existing tabular Q-Learning approach performs when:

* Obstacles can change.
* New dirt can appear.
* The agent has limited observations.

Deep reinforcement-learning methods are reserved for V4.

---

## 17. Training and Evaluation

V2 continues to separate training from evaluation.

### Training

During training, the Q-Learning agent interacts with the dynamic environment.

The agent:

```text
Observe
   ↓
Select Action
   ↓
Environment Changes
   ↓
Receive Reward
   ↓
Receive Next Observation
   ↓
Update Q-Table
```

Training configuration such as:

```text
Episodes
Learning rate
Discount factor
Initial epsilon
Final epsilon
Maximum steps
Random seed
```

will be configurable.

The final V2 training configuration will be recorded after implementation and experimentation.

### Evaluation

After training, the learned policy will be evaluated with exploration disabled.

Evaluation will measure the learned policy under the same configured dynamic-environment conditions.

The evaluation should use controlled random seeds when reproducibility is required.

## 18. V2 Evaluation Metrics

V2 will continue using the main performance metrics from V1:

| Metric                | Description                                   |
| --------------------- | --------------------------------------------- |
| Average reward        | Average episode reward                        |
| Average steps         | Average number of environment steps           |
| Average cleaned cells | Average number of cleaned cells               |
| Completion rate       | Percentage of successfully completed episodes |
| Average invalid moves | Average invalid actions                       |

V2 introduces additional metrics:

| Metric                  | Description                                  |
| ----------------------- | -------------------------------------------- |
| Dynamic obstacle events | Number of dynamic obstacle updates/events    |
| New dirt events         | Number of newly generated dirty cells        |
| Failure rate            | Percentage of failed episodes                |
| Battery failures        | Episodes ending because of battery depletion |
| Observation size        | Size of the agent's local observation        |

These metrics will allow V2 to be compared directly with the V1 baseline.

## 19. V2 Experiments

The primary V2 experiment will compare the learned policy in increasingly difficult environments.

The experimental progression is:

```text
V1 Static Environment
        │
        ▼
V2 Dynamic Obstacles
        │
        ▼
V2 Dynamic Dirt
        │
        ▼
V2 Dynamic Obstacles + Dynamic Dirt
        │
        ▼
V2 Partial Observation
```

The purpose is to identify how each additional source of difficulty affects learning performance.

The V1 results provide the baseline:

```text
100% completion
40.00 average reward
10.00 average steps
3.00 average cleaned cells
0.00 average invalid moves
```

V2 results will be added after implementation and training.
