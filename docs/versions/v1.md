# Version 1 — Autonomous Cleaning Vehicle

## 1. Overview

Version 1 (V1) establishes the first complete reinforcement-learning environment for an autonomous cleaning vehicle operating on a discrete grid.

The objective is to train an agent to navigate a static environment, reach dirty cells, clean them, and complete the cleaning task efficiently.

V1 focuses on building a reliable and testable foundation before introducing dynamic environments or more advanced reinforcement-learning methods.

---

## 2. V1 Objectives

The main objectives of V1 are:

* Represent the cleaning environment as a discrete 2D grid.
* Support configurable grid dimensions.
* Represent static obstacles.
* Represent dirty cells.
* Represent the vehicle's position.
* Define a discrete movement action space.
* Prevent movement outside the grid.
* Prevent movement through obstacles.
* Clean dirty cells when the vehicle reaches them.
* Define a configurable reward function.
* Support battery consumption and charging.
* Detect task completion.
* Implement baseline agents.
* Implement tabular Q-Learning.
* Train and evaluate a learned policy.
* Provide automated unit tests for the system.

---

## 3. Environment

The environment is represented as a rectangular grid.

Each position is represented using:

```text
(row, column)
```

The coordinate system follows:

```text
row    → increases downward
column → increases to the right
```

For example:

```text
(0, 0) ───► (0, 1) ───► (0, 2)
  │
  ▼
(1, 0)      (1, 1)      (1, 2)
```

V1 supports configurable grid dimensions, including the planned 10×10 and 20×20 configurations.

The environment contains:

* Empty cells
* Dirty cells
* Static obstacles
* A vehicle position
* A charging station
* Battery state

---

## 4. State Representation

The V1 RL state contains information describing the current situation of the vehicle.

The state includes:

```text
State
├── position
├── dirty_cells
└── battery
```

The vehicle position is represented as:

```text
(row, column)
```

Remaining dirty cells are represented as a `frozenset` of positions.

The battery represents the remaining energy available to the vehicle.

The state is immutable and hashable so that it can be used as a key in a tabular Q-Learning implementation.

Static environment information such as the obstacle layout belongs to the environment rather than being duplicated inside the state representation.

---

## 5. Action Space

V1 uses four discrete movement actions:

```text
UP
DOWN
LEFT
RIGHT
```

Each action corresponds to a position delta:

| Action | Delta     |
| ------ | --------- |
| UP     | `(-1, 0)` |
| DOWN   | `(1, 0)`  |
| LEFT   | `(0, -1)` |
| RIGHT  | `(0, 1)`  |

The action representation is implemented using an `Action` enum.

The delta associated with an action is used by the environment to calculate the next position.

---

## 6. Movement

For every action, the environment calculates:

```text
current position + action delta
```

The resulting position is checked against the environment.

A movement is valid when:

1. The destination is inside the grid.
2. The destination is not an obstacle.

If the movement is invalid, the vehicle remains in its current position.

This provides deterministic movement behavior for V1.

---

## 7. Cleaning

When the vehicle moves onto a dirty cell, that cell is removed from the remaining dirty-cell set.

For example:

```text
Before:

dirty_cells = {
    (2, 3),
    (5, 5),
    (7, 1)
}
```

After reaching `(2, 3)`:

```text
dirty_cells = {
    (5, 5),
    (7, 1)
}
```

The cleaning operation is therefore represented as a state transition rather than as a separate movement action.

---

## 8. Episode Termination

An episode is considered complete when there are no dirty cells remaining.

Formally:

```text
done = True
```

when:

```text
|dirty_cells| = 0
```

The episode may also terminate because it reaches the configured maximum number of steps during training or evaluation.

---

## 9. Battery and Charging

V1 introduces battery management and a charging station as part of the vehicle environment.

The battery is represented as part of the vehicle state.

Battery-related behavior provides the foundation for more advanced energy-management behavior in future versions.

The charging station provides a designated location where the vehicle can recharge.

Battery management in V1 remains intentionally simple so that the primary focus remains on establishing the basic RL environment and Q-Learning pipeline.

More advanced battery-management strategies are planned for future versions.

---

## 10. Reward Function

The V1 reward function is configurable through `RewardConfig`.

The default reward policy is:

| Event                 | Reward |
| --------------------- | -----: |
| Valid movement        |   `-1` |
| Invalid movement      |   `-2` |
| Cleaning a dirty cell |  `+10` |
| Completing the task   |  `+20` |

The purpose of the reward structure is to encourage the vehicle to:

* Reach dirty cells.
* Clean all dirty cells.
* Minimize unnecessary movement.
* Avoid invalid actions.
* Complete the task.

The reward configuration is separated from the environment implementation so that reward policies can be changed independently.

---

## 11. Agents

V1 contains three agent strategies.

### Random Agent

The Random Agent selects an available action randomly.

It provides a baseline for measuring performance without purposeful decision-making.

### Greedy Agent

The Greedy Agent selects actions based on the nearest remaining dirty cell.

It provides a simple non-learning baseline.

### Q-Learning Agent

The Q-Learning Agent learns a policy using a tabular Q-function.

The Q-table maps state-action pairs to estimated future rewards.

The agent uses epsilon-greedy action selection during training.

---

## 12. Q-Learning

The Q-Learning update follows the standard tabular formulation:

```text
Q(s,a) ← Q(s,a) +
         α [r + γ max Q(s',a') - Q(s,a)]
```

where:

* `s` = current state
* `a` = selected action
* `r` = received reward
* `s'` = next state
* `α` = learning rate
* `γ` = discount factor

During training, epsilon-greedy exploration allows the agent to balance exploration and exploitation.

As training progresses, epsilon decreases.

For the final V1 experiment:

```text
Training episodes: 1000
Final epsilon:     0.0100
```

During evaluation, the learned Q-Learning policy is evaluated greedily with exploration disabled.

---

## 13. Training and Evaluation

V1 separates training from evaluation.

### Training

The Q-Learning agent interacts with the environment and updates its Q-table after each transition.

Final training configuration:

```text
Episodes:       1000
Final epsilon:  0.0100
Q-table size:   10816
```

### Evaluation

After training, the learned policy is evaluated over 100 episodes.

Exploration is disabled during evaluation so that the evaluation measures the learned policy rather than continued random exploration.

* Random baseline

* Dirt appearing over time
* Partial observability
